# StoryForge 社区作品集

此目录是 `my-website` 中独立的 `/community-works/` 子应用。原个人项目展示仍由仓库根目录 `index.html` 提供。作者可在网站点击「我要投稿」，用邮箱登录后填写公开笔名、作品名和章节，预览并确认发布权。也可在支持社区分享的 StoryForge 版本内选择小说章节或既有文档解析的拆书分析。投稿成功后凭编号在「我的投稿」查看进度，审核通过后公开。浏览无需登录，投稿及互动验证邮箱。

## 交付与运行边界（2026-11-03）

社区正式地址为 `https://yuanbw.vercel.app/community-works/`，官网的“社区作品集”链接由 `storyforge-platform` 单独交付。客户端源码使用正式公开连接配置，正式安装包由维护者在合并后构建。各环境的实际收稿、发布和社交状态由服务端开关控制，不能从源码推断线上已开启。

熔炉 `/manage/` 的“社区作品”已经接入统一管理登录。2026-11-03 本人已验证只输入管理口令即可进入，刷新和重新进入保持有效；原独立审核地址保留邮箱与 TOTP。正式与预览使用两个独立 Supabase 免费项目，预览不连接正式稿库。旧项目展示和既有子应用不变。

上线规则见 `/community-works/policy`：明确运营主体、公开联系渠道、内容标准、先审后显、境外服务处理、撤回与删除差别、保留范围及免费限额。初始示例必须明确标为示例并经过同一审核流程；不上传私人稿件，不制造点赞或送花数据。

2026-11-03 已完成数据库自定义格式备份及隔离 PostgreSQL 17 恢复：26 张社区表逐表行数和摘要一致，RLS 均保留；10 个私有 Storage 对象另行备份并逐字节校验。备份采用 AES-256-GCM 加密保存在仓库外，恢复密钥独立于 Git。此证据验证数据恢复，不冒充整套 Supabase Auth/Storage 跨云容灾切换。后续备份须继续同时包含数据库和对象，不能只备数据库。迁移、批量处置前先备份；定期恢复核对，保留至少两个成功批次。

## 本地验证

```sh
cd community-works
npm ci
npm test
npm run test:browser
npm run build
```

根目录 `build.mjs` 负责将本子应用的构建输出复制到 `public/community-works/`，Vercel 的定向 rewrite 覆盖作品详情、投稿状态及其余版本化 API 路径。社区使用 `api/community.mjs` 一个 Vercel Function 入口，处理代码留在本目录的 `server/`；以单入口路由避免把每个辅助模块都计算为独立 Functions。`.mjs` 明确使用原生 ESM，避免无根级 `package.json` 时 Vercel 将入口编译为 CommonJS，再以 `require()` 加载 ESM 子模块导致运行时启动失败。

跨域客户端联调时，受保护的 Vercel Preview 还需将 `/api/community/v1/` 加入 [OPTIONS Allowlist](https://vercel.com/docs/deployment-protection/methods-to-bypass-deployment-protection/options-allowlist)。它仅放行预检，实际请求仍需预览访问凭据和社区用户身份；不能关闭整站保护或把凭据编进客户端。应用层先核对精确 Origin、处理预检，再判断方法与用户权限，错误响应也带合法来源的 CORS 头。作者列表、撤回和申诉共用此顺序；未授权来源返回 403，合法来源的未登录请求仍返回 401。

## 数据与权限

1. 依次应用 `supabase/migrations/` 中的迁移。迁移会把专用 `community-intake` 桶设为私有并收紧文件大小与 MIME 类型，部署后仍须读回桶设置和对象策略；公开目录的 RLS 只允许读取 `published`。上传会话由 `community_allocate_upload_session` 在数据库事务内按作者与幂等键分配，每天最多 10 次。迁移 020 对每个未验证且未清理的会话预留完整 32 MiB，过期也不提前释放；已验证且仍存在的不可覆盖对象按实际大小与声明大小的较大者计入，缺失对象继续保留完整额度。Storage 中无会话归属或仍存在于清理回执之后的对象也计入，合计加上新预留超过 750 MiB 时暂停新分配。正常续传复用原预留；桶配置漂移、对象大小未知或历史超配时停止签发新目标。这里只约束社区桶的已完成对象与分配预留，不是组织级免费额度或费用保证：其他项目/桶、TUS 临时分片、数据库、带宽与邮件仍须分别监测。返回状态可用同一上传会话 ID 查询，避免网络回执不明时重复投稿。
2. Vercel 环境中设置服务端 `COMMUNITY_SUPABASE_URL`、`COMMUNITY_SUPABASE_PUBLISHABLE_KEY`、`COMMUNITY_SUPABASE_SECRET_KEY`、`COMMUNITY_ALLOWED_ORIGINS`；只有前两项的公开值另外以 `VITE_COMMUNITY_SUPABASE_URL`、`VITE_COMMUNITY_SUPABASE_PUBLISHABLE_KEY` 供页面构建。**绝不**给 secret key 使用 `VITE_` 前缀。作品集页面与其 API 的同源请求按实际部署 origin 通过；`COMMUNITY_ALLOWED_ORIGINS` 只列出跨站调用的 StoryForge 网页 origin、桌面客户端固定的 `http://localhost:17831`、Android 客户端的 `https://localhost`，不要用 `*`。预览和正式环境分别配置，不能让预览版使用正式库。`COMMUNITY_ACCEPTING_SUBMISSIONS=1` 才分配上传目标；默认暂停。
3. Supabase Edge Functions `verify-submission` 与 `review-submission` 需要 `COMMUNITY_PUBLISHABLE_KEY` 和 `COMMUNITY_SECRET_KEY` 私有环境变量。前者同样需要 `COMMUNITY_ACCEPTING_SUBMISSIONS=1` 才定稿，后者需要单独设置 `COMMUNITY_PUBLISH_ENABLED=1` 才公开。`supabase/config.toml` 关闭平台级旧 JWT 检查；函数内部使用用户 JWT 向 Auth 服务重新验明身份，再检查审核员成员表。
4. 投稿文件由客户端直传 Supabase 私有 Storage，Vercel 只处理小型控制请求。Edge Function 重新计算完整字节 SHA-256、校验所选内容白名单，再创建仅作者可查状态的 `submitted` 记录。审核通过后继续引用该不可覆盖的原始对象；公开正文由服务端先检查已发布状态与哈希，再按片返回，不授予匿名对象读取权限。上传完成或创建投稿均不会自动公开。当前不依赖 Cloudflare R2。
5. 审核员名单默认没有激活成员。审核台先通过服务端成员资格预检，再要求审核员用身份验证器完成 TOTP 二次验证；所有私有审核队列、审核决定、举报处理和申诉决定都在服务端同时检查当前会话为 `aal2` 与激活成员资格。只绑定验证器或普通邮箱登录不足以审核。审核状态转换通过 `community_review_transition` 单一数据库事务完成，检查审核员、精确修订哈希及合法转移；匿名只读 `published`。目录和正文按页/片读取，避免 Vercel 4.5 MB 响应限制。举报走私有事务；审核员下架与报告审计在同一事务生效。
   作品列表每次最多返回 50 条；页面通过“加载更多作品”继续读取后续已公开作品，切换类型或搜索词时从第一页重新开始。
6. 整部作品、章节、段落和划线评论支持一层回复：登录后提交，默认 `pending`，模型完整通过或独立人工审核批准后才公开；读者可举报评论，审核员处理后可原子下架。`/community-works/me` 只读取当前登录作者的投稿与申诉；作者撤回与公开作品隐藏在同一事务内完成。申诉经过人工复核，即使被支持也不会自动重新发布，作者需提交新的待审版本。
7. 网页和客户端均使用邮件 **OTP 验证码**，不是邮件中的自动登录链接。Supabase Auth 的 Magic Link/OTP 邮件模板须明确呈现 `{{ .Token }}`，配置可运维 SMTP、发信域名和速率限制，再分别验证网页、Electron、Android 的登录与退出。测试账号和审核员账号须分开；审核员只能由受控数据库管理流程设为 active，不能通过前端自助取得权限。

隔离联调项目已应用全部 20 个迁移，部署三项 Edge Functions，并将连接配置限定在当前作品集分支的 Vercel Preview 环境。远端读回显示 26 张社区表全部启用 RLS、私有桶限制为 32 MiB、匿名可读空目录但不能读取私有投稿或审核员表；匿名调用投稿定稿和审核接口分别被暂停开关与审核员门禁拒绝。真实 Supabase 测试账号在本轮创建并删除：登录、作者私有会话可见、匿名会话/对象不可见、审核员表拒绝普通账号均通过。新建免费项目的 Data API 不会默认授予新表的服务端权限，迁移 012 明确只给社区服务端直接读取、会话更新和已验证投稿插入所需权限。已激活一位审核员并核对其验证器绑定，公开作品仍为零，收稿、发布开关均关闭。正式环境没有配置这些值。

当前本地 106 项 Node/PGlite 测试验证迁移、最小权限、精确修订、幂等、审核、撤回、下架和实际容量预留。16 个桌面/手机隔离浏览器场景通过，包括书架续读、划线评论先审后显、作者回复、消息定位、屏蔽/解除屏蔽，以及送花响应丢失后只确认原请求。浏览器测试运行真实页面、API handler 与 PGlite，使用合成 Auth/Storage 适配，不代表托管服务或真实设备已完整验收。

测试后端 PostgreSQL 另已执行整笔回滚的合成事务：每日领花与赠送幂等、余额不足拒绝、私有书架、待审隐藏、作者回复、屏蔽与下架均通过；测试身份、作品和花花流水均未提交。Brevo SMTP 与验证码模板已配置，QQ 邮箱真实收信和登录已确认。托管合成投稿、TUS 断线恢复和受控模型发布的后续证据见下文；审核员 TOTP 再次登录、失效会话拒绝与实际桌面/手机宽度的页面操作已另行完成；安装包范围见下文，收稿及发布保持关闭。

## 阅读互动

社区各页使用统一的紧凑标题与内容区：首页直接显示分类、搜索和作品卡片；阅读空间按书架网格、站内消息、花篮和屏蔽管理组织，花篮收支在区域内滚动；我的投稿以中文状态、时间及操作展示记录，编号和更新时间按需展开。登录和规则页使用同一字号尺度，手机保留可触达的按钮与完整标题。投稿加载失败时隐藏旧记录，刷新成功后再提供操作。

作品详情采用紧凑阅读布局：桌面左侧为可独立滚动的章节或分析目录，右侧显示正文；手机使用目录选择框。拆书默认打开第一项已公开分析的首条内容，切换目录只加载当前维度；原有章节分页、未公开范围提示和精确阅读位置链接继续有效。标题与作者信息完整保留，点赞、收藏、送花集中为紧凑工具栏。

- 作品页可点赞、取消点赞、收藏和追更。顶栏“阅读空间”包含私人书架、站内消息、花篮和屏蔽管理。段落旁的“读到这里”保存当前公开版本与位置，书架的“继续上次阅读”返回同一版本；新版本另有提示。
- 点击“讨论本章 / 本条分析”、段落旁“讨论”，或选择同一段内最多 500 个字符后点击“划线评论”。网页与服务端共用 Unicode 规范化、代码点偏移和 SHA-256 协议，服务端从哈希验证过的正文检查选区。更新不会把旧评论猜测迁移到新文本。评论/回复最多 1200 字符、每日合计 10 条，全部先审后显；作者徽标从真实作品 owner 判定，昵称不能伪造徽标。
- 花篮每天北京时间 0 点恢复领取资格，每日免费领 3 朵，最多存 30 朵，单次送 1–3 朵，不能送给自己的作品。花满时不消耗当日资格。没有充值、转账、提现或兑换。数据库账号锁、唯一键和同一事务保护余额与不可变流水；网络结果未知时持久保存原请求，刷新后继续确认，不生成第二笔赠送。
- 站内消息包括投稿状态、审核通过的回复、追更作品的新公开版本与送花事件。消息只属于接收者，不逐条发邮件。举报和下架复用审核台；回复也显示正文锚点与父评论。撤回根评论会隐藏回复入口；下架作品会隐藏正文、评论与通知链接。
- 作者可在“我的投稿”中为仍处于 `submitted` 的稿件显式选择“更新已有作品”；服务端验证同一 owner 和作品类型，开始审核后锁定关联。未选择时作为独立作品，绝不按同名标题合并。点赞/收藏/花数随稳定作品保留，正文、评论锚点和阅读位置仍绑定不可变修订。

## 社交数据运维

迁移 013–016 依次新增社区作品身份、私人社交表、评论锚点、通知和不可变花花流水；现有公开快照逐份建立稳定身份，保留原 slug/hash/正文对象。新增表均启用 RLS，匿名和普通账号不能直接读写，带 actor 参数的 RPC 只授权服务端。BFF 从 Supabase Auth 验证会话，拒绝客户端提交的未知身份字段。私人列表每页最多 50 条，点赞/书架/屏蔽每账号各限 2000 项。

`COMMUNITY_SOCIAL_WRITES_PAUSED=1` 可暂停新增评论、领花、送花及收藏等互动，同时保留撤回评论、移出书架、解除屏蔽和消息已读。该开关独立于收稿/发布开关。回退界面时保留数据库和流水，禁止通过删除新表或改写流水回滚用户行为；需要纠正已落库数据时另做受审查的向前迁移。长期容量/留存、异常账号处置与告警仍属于正式开闸前的运营验收。

- 指定实际审核值班人员、权利投诉和紧急处置联系人，明确地区、隐私、版权、未成年人保护与内容政策、生效日、留存/删除方式、申诉和举报渠道；出现不能裁决的具体法律问题时另行咨询，不宣称覆盖所有国家。先在 `/community-works/policy` 发布正式规则；默认暂停收稿与发布，审核容量不足时保持暂停。
- 为预览/正式环境分别配置数据库、密钥、邮件、允许的 Origin、监控和备份。先只开放预览的测试账号，核对 Vercel Preview 旧首页与其他路径不受影响，再做正式迁移/部署和少量真实人工演练。正式页确认有已批准样本且公开/私有权限符合预期后，才移除 `noindex`、增加官网入口并交付含公开配置的客户端构建。
- StoryForge 网页、桌面和 Android 的发行构建需带同一组公开配置：`VITE_STORYFORGE_COMMUNITY_SHARING=1`、`VITE_STORYFORGE_COMMUNITY_API_URL`（作品集 Vercel origin）、`VITE_STORYFORGE_COMMUNITY_SUPABASE_URL`、`VITE_STORYFORGE_COMMUNITY_SUPABASE_PUBLISHABLE_KEY`。这四项在构建时写入静态资源；不能把服务端 secret key 带入客户端。分别在三端真实打包后验证邮箱验证码、私有直传、投稿回执和重新启动后的恢复，再公开下载。


## Agnes 自动审核与人工接管

新增迁移 017、018：审核设置、逐修订任务、逐次模型调用记录和审核员私有提醒。它们不读写 StoryForge 本地手稿、生成任务或作者采纳字段。人工审核和模型公开共用一个作品投影写入函数；审计区分 `human` 与 `model`，模型不冒用审核员账号。普通账号不能读写这些表，也不能直接调用带 actor 或 lease 的内部 RPC。

- `auto-moderate` 是受专用服务端令牌保护的 Edge Function；Agnes 端点与 API 密钥仅存于该项目的 Edge Secrets。固定 `agnes-2.5-flash`，调用 JSON 输出模式，并独立严格校验结果。不启用工具、不访问投稿链接、不把投稿文字当成指令。
- 只读取投稿人明确选择的不可覆盖快照、公开笔名，以及待审评论必要上下文。共享的人审/机审加载器验证对象路径、32 MiB 字节预算、完整 SHA-256 和快照 schema，再遍历全部文字字段。每段最多 8000 Unicode 字符，邻段重叠 500 字符；两次新调用互不读取对方结论。最多 48 段、96 次检查，序列化内容超过 360500 UTF-16 代码单元时完整保留原稿并交人工，绝不截断后声称全稿通过。
- 默认每天最多预约 200 次模型请求，UTC 日界、全站一个进行中租约。一次 worker 最多一次模型请求；网络、格式、限流或权限失败均不盲重试。过期租约标记结果不明并通知人工；权限错误、限流或配置错误会暂停自动审核。每日额度耗尽的任务进入人工待办，不会隐蔽续费或换模型重发。
- 每段两次均明确通过后，仍须数据库 `enabled`、`auto_publish` 和 Edge `COMMUNITY_PUBLISH_ENABLED=1` 同时满足才可公开。任何疑点都转人工，不自动拒稿、删除、封禁；人工决定、撤回和版本变化优先，举报和申诉保留人工处理。模型分类不等于版权证明、跨地区法律合规或零漏判保证。
- 审核员登录后在顶部看到待复核数量；进入审核台必须重新满足服务端成员资格与 `aal2`。疑难项优先显示，可打开原稿或定位待审评论。当前是**站内提醒**：没有承诺关闭网页后仍有手机或邮件推送。现有邮箱验证码额度不用于逐条审核通知。

调度按 Supabase 官方 `pg_cron` + `pg_net` + Vault 方式部署，仓库提供 `ops/automod-scheduler.sql`。Vault 只给定时任务提供函数 URL 与专用调用令牌，不放模型密钥或数据库管理密钥。定时器每分钟检查队列，无待处理任务不发请求；模型在数据库中仍受租约和每日调用预算限制。`pg_net` 会短暂保存 HTTP 请求头，因此数据库运维权限必须受限。暂停时先设 `enabled=false`，必要时 `cron.unschedule('community-automod-minute')`；保留稿件、任务、调用和历史审计，不删表回滚。

## 统一管理登录

按用户最新要求，日常审核仅登录熔炉后台一次。内嵌协议 v2 由父页面通过现有 Cookie + CSRF 申请短时审核专用授权，严格核对双向 Origin、来源窗口、随机 nonce 和授权有效期；在内存中保存并自动续接，不再提示邮箱验证码或 TOTP。刷新复用有效管理登录，退出管理后台后后续审核请求失效。

境外 BFF 和 review-submission Edge Function 用仅服务端的 `COMMUNITY_MANAGEMENT_VERIFIER` 向固定 `https://storyforge-lab.com/v1/management/community/verify` 在线核实授权；无缓存、禁止重定向、失败拒绝。响应必须匹配当前后端 Origin、指定审核身份和短有效期，并继续读回激活审核员资格。该凭据不能签发授权或访问其他管理接口。公开前端、Git 与客户端不含此密钥。

这是独立的管理鉴权方式，不伪造 Supabase 用户会话或 `aal2`；原独立审核入口的 MFA 检查保留。审核授权只在作品/评论审核、举报、申诉、模型待办和运行概览生效，不能作为普通用户投稿、送花或撤回作者作品。修订 SHA、拒绝自审、审核状态转换、数据库 owner 和审计保持原样，无数据库迁移。国内 API 只核实授权，不代理稿件。

统一登录的两仓库检查、Edge/网站/管理服务部署和本人单次登录读回已完成。公开投稿与发布由独立开关控制；统一管理授权不会赋予普通读者审核权限。

## 免费额度与运维

审核台“运行概览”显示上传预留与已用对象字节、待审队列和模型待办。社区桶的 750 MiB 预算及每日 200 次模型预约是程序上限；不能代替 Supabase 数据库/流量、Vercel 请求与流量、Brevo 发信额度。平台额度在各服务控制台查看，不自动升级付费或启用 R2。出现额度不足、投递失败或审核拥堵时暂停对应写入，保留既有作品和审计。

每日清理任务由 `vercel.json` 调度 `/api/community/v1/cleanup`，必须配置独立随机 `CRON_SECRET`，不能复用管理口令。仅处理超过 48 小时且没有绑定投稿的上传会话，删除精确对象并写入清理回执；已提交、撤回、拒绝稿均不在该清理范围。启用前以隔离数据验证未提交对象被清理、已提交对象保留；部署后验明匿名调用拒绝，并保存第一次授权执行结果。请求失败保留错误，不扩大删除范围。

回退顺序：关闭 `COMMUNITY_ACCEPTING_SUBMISSIONS`，设置 `COMMUNITY_SOCIAL_WRITES_PAUSED=1`，关闭 Edge `COMMUNITY_PUBLISH_ENABLED` 和数据库自动发布，再回退界面。保留数据库、对象、版权与审核事件以及花花流水，禁止用清空数据回滚。
